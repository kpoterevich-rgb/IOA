# OlympIA — подготовка к публичному запуску

В этом пакете находится текущая версия сайта OlympIA и заготовки для безопасного серверного слоя.

## Важно: это ещё не готовый публичный релиз

Текущий `index.html` — одностраничное приложение, в котором часть данных сохраняется в `localStorage`. Поэтому сейчас:
- профили, собственные олимпиады, настройки редактора и рейтинг не являются общей базой для всех посетителей;
- пароль администратора находится в клиентском JavaScript и не может считаться секретом;
- редактор сайта сохраняет изменения только в браузере, где их внесли;
- `/api/ai-tutor` требует серверный обработчик, которого в статическом HTML нет;
- генерация/перевод заданий использует внешний сервис перевода без гарантии доступности или стабильности;
- перед публикацией нужно проверить права на обработку персональных данных, возрастные требования, тексты правил и политику конфиденциальности.

Не публикуйте текущий файл как полноценный соревновательный сервис до завершения этапов ниже. Иначе участники могут видеть разные рейтинги на разных устройствах, а административная зона не будет защищена.

## Предлагаемая архитектура

- **Frontend:** текущий `index.html`, после интеграции с серверным API.
- **Hosting:** GitHub Pages или другой статический хостинг для frontend.
- **Database/Auth:** Supabase (Postgres + Auth + Row Level Security).
- **AI tutor:** Supabase Edge Function; секрет API хранить только в Secrets, никогда не в HTML/JavaScript.
- **Scoring:** считать результат на сервере. Не отправлять правильные ответы в браузер до окончания олимпиады.
- **Admin:** роль назначать на серверной стороне в `app_metadata`; не использовать пароль, зашитый в HTML.
- **Privacy:** собирать только необходимые данные, показывать политику конфиденциальности и срок хранения данных.

## Порядок запуска

1. Создать проект Supabase и сохранить URL проекта и anon key.
2. Выполнить `supabase/schema.sql` в SQL Editor.
3. Назначить владельцу роль `admin` через Supabase Auth / защищённый серверный процесс. Не добавлять роль через публичную форму сайта.
4. Настроить и развернуть Edge Function из `supabase/functions/ai-tutor`.
5. Заменить клиентские функции `localStorage` на API Supabase: профили, опубликованные олимпиады, задания, попытки, рейтинг и настройки сайта.
6. Перенести проверку ответов и подсчёт баллов в серверную функцию; хранить ключи правильных ответов отдельно от публичных заданий.
7. Настроить домен/HTTPS, страницу конфиденциальности, контакт для обращений и политику удаления данных.
8. Провести тесты на мобильном устройстве и компьютере, включая одновременных участников, истечение таймера, повторную отправку ответов, права администратора и изоляцию данных.
9. Только после этого опубликовать frontend.

## Что не нужно помещать в репозиторий

- `OPENAI_API_KEY` или любой другой секрет;
- пароль администратора;
- токены доступа;
- выгрузки с реальными email/профилями участников.

## Проверка текущего файла

На момент подготовки в HTML найдено 15 встроенных JavaScript-блоков; все они прошли синтаксическую проверку Node.js. Это не заменяет проверку в браузере и проверку логики всех сценариев.
